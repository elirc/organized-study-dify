# Technology Best Practices

This suite teaches how Dify uses its main technologies in real code. It is not a generic React, Flask, or SQLAlchemy guide. Each lesson points back to actual files in this repository so you can practice reading production patterns instead of memorizing framework trivia.

Use this suite when you want to study one technology at a time:

1. Start with `01-technology-map.md` to see what matters most.
2. Use `02-real-code-patterns.md` to study concrete examples.
3. Read `03-cross-cutting-engineering-lessons.md` when you want senior-level judgment across layers.
4. Follow `04-practice-plan.md` as a 30-day training path.

This differs from the architecture suite because the architecture suite asks, "How does the whole system fit together?" This suite asks, "How does this codebase use each tool, and what should I copy or avoid when building?"

To turn a pattern into practice, pick one file, explain the owner and boundary out loud, then make a tiny local experiment on a branch you can discard. Do not start by changing five layers. A stronger engineer learns to preserve the shape of the system before extending it.
